# Project guide

1.3.6: core.js owns correctRecord/confirmIssue and terminal result recovery. Keep unrelated gaps and archive corrected mainlines. Legacy tail warnings resolve only with a legal terminal mainline; other issues require explicit confirmation. CapturePipeline freezes completed ordinary games while retaining exercise undo. Run review-correction.test.js, review-correction-smoke.js (CORRECTION_ANDROID=1 for installed APK), and TerminalCaptureTest.

1.3.5: BoardRecognizer copies only the exact sampling ROI and reuses coordinate/color buffers. YuvFrameConverter uses pixel-equivalent lookup tables; ScreenFrameConverter skips redundant same-size drawing. RecognizerSamplingTest compares the frozen ReferenceBoardRecognizer. ExperimentalVideoFrameReader is androidTest-only and is not the production importer. Keep original sampling/thresholds; benchmark and private fixtures stay separate.

1.3.4: YuvFrameConverter reuses scratch arrays without changing pixels; PrefetchedVideoReader has bounded lookahead; ScreenFrameConverter reuses capture bitmaps. Run FrameConversionTest and VideoPrefetchTest, then compare the same private full video and real MediaProjection replay. Keep private inputs and game records out of source control.

1.3.3: New exploratory forks auto-save after three new plies; explicit saves and uninterrupted extensions remain available at any length. Run review-branch-comparison-ui.js and review-capture-regression-ui.js. VideoRegressionTest requires private regression-video.mp4 and regression-reference.json supplied in the app external files directory. review-video-screen-replay.js replays that local video through MediaProjection. Never publish these inputs or resulting private game records. Video import targets games without takebacks; use screenshot import for exercises.

Android recorder module :recorder; shared static UI in review/; vendored rules, engines and licenses in vendor/. Build outputs stay in android/recorder/build/ and must not be committed. docs/images/ contains presentation screenshots; docs/examples/ contains the verified public demonstration PGN.

Run npm test and npm run test:ui for JavaScript. In android/, run gradlew :recorder:testDebugUnitTest :recorder:lintDebug :recorder:assembleDebug. Android instrumentation needs the Release vision fixture archive extracted into android/recorder/build/reports/; fixtures must never enter the main APK. Keep package identity and persistent storage compatible. Do not publish account information, secrets, emulator data, signing keys or full user screen recordings.

Presentation scores follow the board orientation; stored engine scores remain white-centric. New demos are ephemeral. review/demo-analysis.js contains verified depth-20 Stockfish 19 results generated with tests/prepare-demo-analysis.cjs; see review/demo-analysis.md for provenance. Run tests/review-demo-android.js to check native demo isolation.

1.2.0: review/themes.js selects board/piece appearance; review/assets/pieces/ contains original SVGs generated by tests/prepare-review-pieces.py. review/board-motion.js animates legal transitions. WDL arrays are white win/draw/loss integer permille, summing to 1000. Missing legacy WDL requires analysis. Retain the chart control DOM during pointer capture, including Android range touches without focus.

1.2.1: realtime capture reuses valid static frames and ignores this app foreground. Bundled numeric board features are in review/assets/duolingo-board-profile.json.gz; AAPT packages the decompressed .json asset. Preserve source/packaged hash verification in inspect_apk.py. Generate the rollback clip with tests/review-capture-regression-video.py after extracting the v1.1.0 fixtures. Run tests/review-capture-regression-ui.js plus native instrumentation. Live feedback defaults on and must respect its persistent setting; overlay UI must never intercept board touches. Never commit physical-device screenshots or private capture records.

1.3.0: review/analysis-policy.js owns automatic analysis bounds and progressive passes; unlimited search requires an explicit preference and must stop on navigation/background. review/library.js owns separate favorite folders and backup ID mapping. src/controlMap.js is shared with the original training project. Branches retain the existing record schema and cache by FEN. Test with tests/review-variation.test.js, review-variation-smoke.js, review-variation-android.js and native StockfishPlayTest. UI fixture results must remain distinct from native engine/video evidence.

1.3.1: battle-clock.js owns paused/active clocks and increments. Whole-game analysis captures its queue independently of browsing. Multi-step transport playback uses a 1.2-second wall clock. Five approved raster sets each have day/night sprites, plus eight boards; per-style size is persisted. System/manual appearance changes preserve WebView and active position. Numeric vision profiles select by board brightness and retain the other calibration. Run review-session*, review-navigation-smoke.js, review-theme-smoke.js and review-night*. AppearanceVisionTest requires separately provided private official-day.jpg and official-night.jpg in the test app external files directory; never commit these screenshots.

1.3.7: Shared review remains the only UI source. ios/ contains Swift/WKWebView, native C++ Stockfish, screenshot recognition, project generation and simulator tests. Build assets and private fixtures stay under ios/build/. ReplayKit and video import are not implemented. Use ios/README.md for reproducible generation and testing. Android adds UpdateChecker and record/import ownership checks; run review-audit tests, StorePolicyTest and ReleasePolicyTest. Preserve deeper analysis, current correction cursor and backup linkage. Do not commit certificates, tokens, personal paths or private fixtures.
