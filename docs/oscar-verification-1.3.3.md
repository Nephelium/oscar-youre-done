# 1.3.3 验证记录

日期：2026-10-21。Windows、Edge 与 Android 16 / API 36.1 x86_64 模拟器。包名 `com.jingjing.chesssprout`，版本 1.3.3 / 10。

## 私有完整录屏

用户授权的约 275.30 秒 H.265 录屏，720×1280，带黑边。起点选择 4.100 秒的初始棋盘。测试输入、画面和完整棋谱仅留在本地，未放入仓库或发布包。

- 最终 APK 的完整导入耗时 **74.620 秒**，包含读取、预览与起始局面准备约 **6.881 秒**。其后识别阶段约 **67.740 秒**。
- 67 个半回合全部与参考棋谱一致，未解决校对项为零。参考由逐局面核验得到，其中 64 个局面直接从画面检查，3 步通过唯一合法路径补全。该样本结果不等于其他录屏的准确率。
- 共采样 1319 帧，1094 帧完成棋子分类，225 帧复用静止结果。画面转换累计约 18.152 秒。当前模拟器使用 `c2.goldfish.hevc.decoder`。
- 同文件、同 5.2 秒起点的识别阶段对照：1.3.2 为 327.187 秒；修复版本多次为 84.660～111.035 秒，均得到其后的 66 步。这里的对照不包括导入准备，不能与上面的完整导入直接相除。
- 早先完整导入曾测得 120.513 秒。运行负载和设备解码器会影响耗时，74.620 秒是最终包的本次结果，并非所有手机的承诺值。

## 实时屏幕采集

- 在 Chrome 中以 **1 倍速**播放同一段原始私有录屏，通过真实全屏 MediaProjection 采集。最终 APK 从初始棋盘一直跟到结束，67 步全部匹配，未解决校对项为零。播放及结束保存约 275.880 秒。
- 覆盖最后密集的王与皇后往返走子。全屏采集所见画面另外包含浏览器工具栏和黑边，并未直接将视频解码帧传给采集流水线。
- 前次完整回放已正确记录 67 步，但结束页被误判成全空棋盘并新增校对项。本版将无双方王的画面按棋盘消失处理，新增原生回归后，再次完整原速回放通过。
- 这证明当前模拟器可跟上该样本的实际节奏，不是物理手机测试，也不等于所有走子速度均可保证无遗漏。

## 已排除的实验

- 在 YUV 阶段比较画面、跳过 RGB 转换：完整 67 步正确，但耗时 133.830 秒，仅复用了 72 帧转换，未证明收益，已从正式实现移除。
- 每 2 秒取样、唯一两步补齐、失败时递归取中间帧：180 秒预算内处理到约 144 秒、读了 1753 帧，停在 12 步。该原型失败，未采用。稀疏取帧仍依赖准确的独立局面识别，反复随机取帧的解码成本也不能忽略。
- 保留顺序解码、减少像素索引重复计算、严格约束棋子距离缓存复用。分类阈值未放宽。

## 分支与界面

- 连续试走一步再撤回，不新增保存分支。未保存路线需要 3 个新半回合；已有路线中途分岔时从分歧处重新计数。
- 手动保存一至两步正常，退回较早一步后保存只保存到当前游标。沿已保存路线延伸时保留分支 ID，原路线和真正分岔分别保存。
- 截图手记没有实战步数时，实际拖动、键盘操作、起点往返与切换对比分支均通过。
- 录屏起点支持小数秒、分钟输入、Enter 定位；验证空值、60 秒非法值、时长末端和定位后保留裁剪框。
- 复盘、自动分析、导航、对战、收藏夹、日夜主题、窄屏及横屏回归通过。
