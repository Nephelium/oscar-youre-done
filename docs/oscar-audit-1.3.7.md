# 奥斯卡你完了 1.3.7：代码审查与界面修订

日期：2026-10-23。基线为公开的 1.3.6，本轮先完成本地 APK 验收，版本号 1.3.7，versionCode 14。

本轮确认并处理了七类代码问题，补充 GitHub 更新检查，同时调整复盘、弹窗与设置的排版。审查采用源码检查、最小失败输入、界面操作、原生单元测试和模拟器安装验证。没有把通过这些检查表述为全机型无缺陷。

## 1. 发现与修复

### P1：补录撤回后，保存仍带入已经撤回的走法

- 位置：`review/app.js` 的 `saveCorrection`、`confirmCorrection`。
- 触发：补走 e4、e5，退回 e4，再保存校对。
- 原因：保存使用整条 `branch`，没有按当前 `branchPly` 截取。确认文案也按整条变化长度计算。
- 修复：确认与保存均采用当前游标之前的走法。退到零步时不允许保存空补录。
- 验证：真实浏览器操作两步、撤回一步、保存，持久化主线只有 `e2e4`。既有 Android 校对测试同时验证胜负、提示清除、取消确认、修订保留、重启和 PGN 结果。

### P1：备份重复导入后，续录关系仍可能跳回原手记

- 位置：`review/core.js` 的 `prepareImport`，`review/app.js` 的 `importRecords`。
- 触发：已有分段 A、B，再导入同一份备份。副本获得新 ID，但旧逻辑没有同步改写段落关联。
- 影响：副本 A 的下一段、B 的上一段，以及校对入口的续录链接，可能仍指向原记录。
- 修复：先为整批记录建立 ID 映射，再统一映射 `capture.previousId`、`capture.nextId`、`issues.continuationId` 和收藏关系。备份内部含重复 ID 时，在写入前明确报错。演示副本使用普通记录 ID。
- 验证：双段互链、校对入口、ID 冲突、演示 ID 和输入对象不变性测试通过。

### P1：正在导入的手记缺少写入与删除保护

- 位置：`MainActivity.kt`、`GameStore.kt`、`VideoImporter.kt` 和 `review/app.js`。
- 原因：原生桥接原本只保护实时采集中的记录，没有保护录屏导入正在写入的记录。
- 风险：用户修改被后续识别保存覆盖，或删除后流水线再次创建该记录。
- 修复：保存、删除都检查当前录屏任务的记录 ID。流水线创建记录后立即发布 ID。界面在走子和开始补录前检查所有权，提示先停止或等待导入完成。改名在保存成功后才替换内存对象。
- 验证：原生策略测试覆盖相同 ID、无关 ID、导入完成和实时采集。界面模拟导入进行中，走子被阻止且当前分支未改变。没有把这一策略测试表述为已穷举所有并发时序。

### P2：短时手动分析会覆盖已有深度结果

- 位置：`review/app.js` 的 `analyzeFen`，`GameStore.kt` 的 `mergeAnalysis`。
- 原因：此前只有自动分析比较深度。手动分析返回后，前端与原生存储都可能直接覆盖缓存。
- 修复：同一引擎的结果统一按深度比较，较浅结果不替换较深结果。更换引擎时允许更新，避免永久保留旧引擎结果。
- 验证：深度 24 缓存遇到深度 8 的新结果后，界面和保存数据仍保留 24。原生测试另外覆盖更深结果、新引擎和空缓存。

### P2：自适应分析在两轮搜索之间退出，可能漏存刚得到的结果

- 位置：`review/app.js` 的 `analyzeFen`、`pauseAnalysis`。
- 原因：自适应分析先快算，再等待下一轮加深。等待期间没有待处理请求，旧暂停流程依赖请求的 flush，可能没有触发保存。
- 修复：每次自动分析返回即保存。暂停时也同步已有缓存。手动分析保持原生逐局面落盘，避免前端重复全量写入。
- 验证：完成两个快速局面评价，在下一轮等待期暂停，两个评价均已保存。另测整盘分析完成一个局面、正在计算第二个时暂停，已完成结果仍保留。

### P2：异常的可选字段会让整篇合法手记从列表消失

- 位置：`review/core.js` 的 `validate`。
- 失败输入包括 `branches:[null]`、`issues:{}`、`analysis.lines:[null]`。
- 原因：未判断数组或条目类型就访问属性，导致整个记录校验抛错，而列表读取会跳过该记录。
- 修复：独立检查可选字段，跳过无效条目，保留合法主线。非法主线仍被拒绝。
- 验证：这些最小输入均可读取并重放主线；非法 e2e8 仍报错。已有数据在读取时受益，不修改存储 schema。

### P2：收藏夹异常条目会使已有收藏不可见

- 位置：`review/library.js`。
- 原因：空条目直接读取 ID 会抛错；超长 ID 先去重再截断可能产生碰撞；保留名称可与内置收藏冲突。
- 修复：跳过空条目、超长 ID 和保留 ID，保留正常文件夹及收藏映射。
- 验证：混合异常和合法条目的输入中，合法训练收藏夹和默认收藏均保留。

## 3. 自动检查更新

实现位于 `UpdateChecker.kt`，依据 [GitHub 正式 Release 接口](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)。

- 默认开启，启动后后台检查。成功结果缓存 24 小时，自动检查失败后至少间隔 15 分钟再尝试。手动检查可立即重试。
- 使用数值版本比较，处理 `1.10.0 > 1.9.9`，忽略草稿和预发布版。
- 新版必须含已上传完成、大小大于零、位于本项目官方 Release 的 APK。
- 发现新版在首页与设置显示版本和下载按钮。手动检查发现新版时提供确认弹窗。
- 点击后用外部浏览器打开项目的 Release 页面。下载、允许安装和安装由用户操作。
- 仅访问固定项目 API，无 token。只读取发布信息，不发送棋谱、截图、录屏或 Elo。
- 增加 `INTERNET` 权限，WebView 仍只加载本地资产。独立线程不占用引擎任务队列，连接和读取各设置 8 秒超时，响应上限 256 KiB，Activity 销毁时关闭连接与执行器。

真实 APK 已在线取得当前 GitHub 的 1.3.6 发布信息，与本地 1.3.7 正确比较。第二次自动检查使用缓存。未来版本提醒通过受控数据和原生策略测试验证，没有为了测试额外发布虚构版本。网络失败状态通过界面回归验证，未在真实设备上穷举各运营商网络。

## 5. 仍需区分的边界

1. 本轮没有物理手机连接。原生安装、引擎和联网检查运行于 Android 模拟器；图像测试使用已有真实画面序列。本轮没有重新在多邻国完成一盘新的实时实战，也没有重跑整段私有视频性能基准。
2. 识别采样、解码、分类算法没有调整，本轮不作识别速度提升或全机型准确率承诺。
3. APK 同时包含 ARM64 Stockfish 19 和 x86_64 Stockfish 16.1；实际运行验证为模拟器的 x86_64 引擎，ARM64 文件进行了包内一致性核验。
4. lint 剩余 Warning 包括 vendored chesslib 的默认 Locale、ExifInterface 推荐迁移、依赖版本提示、数据提取规则与单色启动图标、KTX 建议。本轮没有为消除提示升级依赖或改变第三方规则库。
5. 未进行断电、存储耗尽、数千篇手记压力或所有 Android 厂商后台限制测试。
6. 本记录的 Android 实际安装证据来自首次本地候选包。发布候选包含随后验证过的 iOS 平台适配，最终发布验证另见 1.3.7 更新说明。
