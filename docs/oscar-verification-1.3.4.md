# 1.3.4 验证记录

2026-10-21，Android 16 / API 36.1 x86_64 模拟器。版本 1.3.4 / 11，包名 `com.jingjing.chesssprout`。用户原始视频、截图和完整棋谱仅保存在本地。

## 同段录屏对照

沿用 1.3.3 的约 275.30 秒、720×1280 HEVC 录屏和 67 个半回合参考棋谱，从 4.100 秒初始棋盘开始。完整导入包含读取、预览和起始局面准备。

| 版本 / 次数 | 完整导入 | 起始准备 | 识别阶段墙钟时间 | 累计画面转换 |
| --- | ---: | ---: | ---: | ---: |
| 1.3.3 本轮基线 1 | 89.832 秒 | 8.440 秒 | 81.392 秒 | 20.837 秒 |
| 1.3.3 本轮基线 2 | 88.552 秒 | 4.255 秒 | 84.297 秒 | 21.728 秒 |
| 1.3.4 优化 1 | 68.846 秒 | 4.175 秒 | 64.670 秒 | 14.862 秒 |
| 1.3.4 优化 2 | 74.127 秒 | 8.030 秒 | 66.097 秒 | 15.683 秒 |
| 1.3.4 优化 3 | 70.021 秒 | 4.163 秒 | 65.858 秒 | 15.290 秒 |

每次均得到精确一致的 67 步、零未解决校对项。每次仍采样 1319 帧，其中分类 1094 帧、复用 225 帧，未放宽识别阈值、降低分辨率或减少采样。新版完整导入平均约 71.0 秒，旧版本轮平均约 89.2 秒，约节省 20%。此前 1.3.3 的 74.620 秒属于另一轮运行，不能拿它和本轮任意一次结果构成固定加速保证。

解码器均为 `c2.goldfish.hevc.decoder`。新版本把下一帧的解码与当前帧识别交错执行，队列容量为一帧，另有至多一帧正在生成。转换的累计线程时间已与识别部分重叠，不能把两者简单相加当作总耗时。底层编解码器没有替换。

只复用转换数组、尚未预读的实验完整导入为 87.474 秒，转换为 13.227 秒，棋谱一致。它表明单独缩短转换并未让完整导入同比加速，减少串行等待是本次另一项有效改动。

## 实时画面转换

同一模拟器对相同 RGBA 输入交替调用旧、新转换，各尺寸先预热 4 次，再测 20 次。数值为单次画面复制、裁剪和缩放的平均时间，不包含识别、采样等待或走子动画。

| 输入尺寸 | 原实现 | 新实现 |
| --- | ---: | ---: |
| 720×1280 | 7.070 毫秒 | 1.097 毫秒 |
| 1440×3200，含行填充 | 29.796 毫秒 | 5.133 毫秒 |
| 1280×720 | 7.220 毫秒 | 1.420 毫秒 |

新旧结果逐像素相等，覆盖横屏、缩放、行填充、连续透明画面。YUV 转换另外覆盖全/有限颜色范围、BT.601/709、裁剪、四种旋转及复用时尺寸与格式变化。曾尝试更换绘制混合模式，但其缩放舍入不等价，已撤回并保留原混合方式。

## 原速实时屏幕采集

- 用 Chrome 以 1 倍速播放同一个原始 HEVC 文件，通过真实全屏 MediaProjection 采集，未把解码帧直接交给识别器。
- 起点为 4.100 秒，实际确认初始棋盘就绪后开始播放，一直跟到 275.296 秒结束。播放与结束保存共 274.931 秒。
- 67 步全部精确匹配参考棋谱，未解决校对项为零，包含末段密集的王与皇后往返走子。
- 走子进度变化时采到的状态中，识别处理耗时中位数 15 毫秒、最大 60 毫秒；画面复制与转换中位数约 10.38 毫秒。这里包含实际屏幕缓冲区读取开销，和上面的内存输入微基准不同，也不代表走子到提示的端到端延迟。
- 采集周期仍为 120 毫秒，仍需连续稳定局面确认。未以放松合法走法或稳定性校验换速度。

回放准备时，模拟器软件图形模式下的 Chrome 出现图形进程崩溃和 HEVC 播放失败，随后使用宿主 GPU 启动模拟器。另一次回放在当前棋盘尚未就绪时过早起播，未能跟踪，不计作完成验证；测试脚本已改为持续确认当前初始棋盘就绪后起播，最终完整测试通过。导入计时对照均在同一轮原始图形配置下完成，未跨配置计算加速比。

## 构建与回归

- 主项目 41 项 Node 测试及四组数据/规则校验通过。两个 Android 模块的单元测试分别为 3 项和 12 项，lint 和构建通过。
- 21 项原生测试通过，包含既有日夜、升变、选中棋子、缺口恢复，以及新增像素一致性、预读帧序和时间戳、取消与异常释放。最后的绘制修订另跑两项转换测试通过。
- 实际安装后，本地 Stockfish 分析、分析持久化、WebView 重载、短分支保存通过。
- 独立发布源码的 27 项 Node 测试和 10 组界面回归通过。时钟恢复测试改为在点击事件内读取恢复值，避免异步读数被恢复后的计时器推进，仍要求精确恢复 900000 毫秒。
- 独立源码构建与主项目包的 207 个 assets/lib 文件逐字节一致，主 DEX 相同。

Android 测试均在模拟器完成，未把这些耗时写作小米或其他实体手机的实测。该视频的全部走法一致证明此样本没有准确性回退，其他视频仍需独立验证。
